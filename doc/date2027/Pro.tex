We utilize the fact that the CCZ has two complementary implementations to our advantage by replacing the left CCZ
gate with~\figref{fig-cnot-t-ccz} and the right with \figref{fig-alt-cnot-t-ccz}. In so doing we can combine their
sum-of-paths to get the below sum-of-paths equation:

\begin{equation}
  \label{eq-toff-tot}
  \begin{aligned}
    &\frac{1}{4}z + \frac{1}{4}a + \frac{1}{4}f - \frac{1}{4}(z \oplus a) \\
    &\qquad -\frac{1}{4}(z \oplus f) - \frac{1}{4}(a \oplus f) + \frac{1}{4}(z \oplus a \oplus f)\\
    &- \frac{1}{4}z - \frac{1}{4}(xy \oplus a) - \frac{1}{4} f + \frac{1}{4}(z \oplus xy \oplus a) \\
    &\qquad + \frac{1}{4}(z \oplus f) + \frac{1}{4}(xy \oplus a \oplus f) - \frac{1}{4}(z \oplus xy \oplus a \oplus f)
  \end{aligned}
\end{equation}

This causes some cancellations, and we are left with:

\begin{equation}
  \label{eq-toff-simp}
  \begin{aligned}
    &\frac{1}{4}a - \frac{1}{4}(z \oplus a) - \frac{1}{4}(xy \oplus a) + \frac{1}{4}(z \oplus xy \oplus a)  \\
    &+ \frac{1}{4}(z \oplus a \oplus f) - \frac{1}{4}(a \oplus f) + \frac{1}{4}(xy \oplus a \oplus f) \\
    &- \frac{1}{4}(z \oplus xy \oplus a \oplus f)
  \end{aligned}
\end{equation}

Observe that the first line in\eqnref{eq-toff-simp} contains only terms that have no dependence on $f$.
That means we can bring them out from the summation to create a relative phase version of the compute
gadget, which we depict in~\figref{fig-dirty-gadget-rp}. This means that we can implement the compute
gadget with the same T-count as a relative phase Toffoli gate. We can similarly formulate an uncompute
gadget that is this gadget's conjugate, in order to uncompute the value for the same cost. This implies
that any intermediate computation using dirty ancilla can be performed with the same cost as a relative
phase Toffoli gate.

The output node will have to implement all 8 terms in~\eqnref{eq-toff-simp}. This means that the T-count of
implementing the output node gadget is 8, so that the difference in T-count between the clean ancilla and
the dirty ancilla decompositions is dependent on the number of these output nodes, which is the number of
output bits of the Boolean function $m$. This means that for an MCT gate, the difference between clean
ancilla and dirty ancilla is 1 T-gate. We can implement these as two RTOF gates.

\subsection{Proposed Method}

Our proposed method is as follows

\begin{enumerate}
\item Get the next node in the traversal of the XAG, usually from the input
\item Create a subcircuit according to~\tabref{fig-gadgets}
\item Pass on this subcircuit to the next iteration of the algorithm
\item If this node fans out into a primary output, or an XOR node that fans out
  into a primary output take the complement of the passed down subcircuit and set
  it to act on the ancilla that the node uses.
\item If the node is dependent on another subcircuit/subgraph, block until that subcircuit is
  processed.
\item Terminate when all nodes have been processed.
\end{enumerate}

\begin{example}
  \label{ex-dirty-xag}
  We again generate the XAG for~\figref{fig-xag}. Starting from $x_5$ and $x_4$, we
  generate the node they feed into as an RTOF, and pass this RTOF onto the next stage of the iteration.
  We also generate the node taking in $x_2$ and $x_3$, and see that it feeds into an XOR node that
  fans out into a primary output. We generate a Toffoli, and block for the other input.
  We next generate that node's fanout to $x_3$, Because this takes in a fanin from a primary
  input and another node, we plug the RTOF passed down from the previous iteration as $A$
  in gadget\#1, and pass this subcircuit down to the next part of the iteration. We move onto
  the XOR node taking in $x_2$. Since that is an XOR, we generate a subcircuit using a CNOT with
  $x_2$ as an input and replace it in gadget\#4 along with the passed down subcircuit, and pass this
  subcircuit down further. We again repeat the AND procedure for the $x_1$ node the XOR feeds into,
  and feed that output to the next step. Once we have reached the last XOR node, we process both
  the Toffoli feeding into it and the other branch, and generate the full circuit. The full circuit

  is indeed 1 more than the T-count of~\figref{fig-xag-qc} after optimizing it to use RTOF to reduce
  its T-count.
\end{example}

\subsection{Pebbling Game}

Boolean Logic Network synthesis methods can also use a method known as a ``pebbling game''.
In such a pebbling game, steps are arranged to compute and uncompute nodes such that the
maximum number of qubits that need to be computed at any one time is less than a specified
number $k$, equal to the number of clean ancilla provided to the

\section{Node-Level Pebbling as Incremental SAT}

Following the classical reversible-pebbling encoding, we introduce a
Boolean state variable $p_{v,i}$ for every node $v \in V$ and time
step $i \in \{0,\dots,K\}$, denoting whether $v$ is pebbled at step
$i$. An auxiliary activity variable $a_{v,i}$ marks whether $v$'s
state changed between steps $i-1$ and $i$. Let $P$ denote the pebble
budget and $E$ the fanin relation ($(v,w) \in E$ iff
$w \in \mathrm{fanin}(v)$).

\paragraph{Initial and final clauses.}
At time $0$ every node is unpebbled; at time $K$ every primary output
must be pebbled and every non-output node must be unpebbled:
\begin{equation}
\bigwedge_{v \in V} \bar p_{v,0}
\;\wedge\;
\bigwedge_{v \in O} p_{v,K}
\;\wedge\;
\bigwedge_{v \notin O} \bar p_{v,K}.
\end{equation}

\paragraph{Move clauses.}
A node may only toggle its pebble state at step $i+1$ if every one of
its fanins is pebbled both immediately before and immediately after
the transition:
\begin{equation}
\bigwedge_{i=1}^{K}\;\bigwedge_{(v,w)\in E}
\Big(\big(p_{v,i}\oplus p_{v,i+1}\big) \rightarrow
\big(p_{w,i}\wedge p_{w,i+1}\big)\Big).
\end{equation}

\paragraph{Cardinality clauses.}
At every step at most $P$ nodes may be simultaneously pebbled:
\begin{equation}
\bigwedge_{i=0}^{K}\Big(\sum_{v\in V} p_{v,i} \le P\Big).
\end{equation}

These three clause families are exactly what \texttt{Z3PebbleSolver}
constructs (\texttt{init}, \texttt{add\_step}, \texttt{solve}), using
Z3's \texttt{PbLe} pseudo-Boolean primitive for the cardinality
constraint and \texttt{Implies}/\texttt{And} for the move clauses. The
solver is invoked \emph{incrementally}: $K$ starts at $0$ and is
increased one step at a time (via \texttt{Solver.push}/\texttt{pop})
until a satisfying assignment is found or a step cap is reached, at
which point $P$ is optionally increased and the search restarts
(\texttt{pebble}, \texttt{find\_min\_pebbles}).

\emph{Feasibility bound.} Because reversible pebbling's overlapping
compute/uncompute phases can require more simultaneous pebbles than
there are primary inputs, no fixed function of $|V_{PI}|$ is a safe
upper bound on $P$; the framework instead bounds escalation by
$|V|$, the only value guaranteed sufficient, and by $|O|$ as a lower
bound (since every output must be pebbled simultaneously at $K$).

\section{Gate-Group Construction}

To reduce problem granularity before re-solving at a coarser level,
every primary-input-to-primary-output path in $G$ is traversed and
partitioned into \emph{gate groups}. Each group $g$ carries two node
lists: $\mathrm{clean}(g)$ (nodes whose value is retained as the
group's output and later explicitly uncomputed or preserved as a PO)
and $\mathrm{dirty}(g)$ (transient workspace nodes, freed once the
group finishes). Algorithm~\ref{alg:gategroup} summarizes the
traversal.

\begin{algorithm}
\caption{Gate-group construction from PI--PO paths}
\label{alg:gategroup}
\begin{algorithmic}[1]
\State $\mathit{visited} \gets \emptyset$; $\mathit{gates} \gets []$
\State $g \gets$ new empty gate; $c \gets 0$ \Comment{running dirty count}
\ForAll{PI$\to$PO path $\pi$ in $G$}
  \For{$v \in \pi$ in order}
    \If{$v \in V_{PI}$} \State \textbf{continue} \Comment{always available}
    \ElsIf{$v \in O$}
      \State add $v$ to $\mathrm{clean}(g)$; finalize $g$; $c\gets0$
      \State \textbf{break} (path fully consumed)
    \ElsIf{$v$ is XOR $\wedge\, v \notin \mathit{visited}$}
      \State add $v$ to $\mathrm{clean}(g)$; finalize $g$; $c\gets0$
    \ElsIf{$c = P-1$} \Comment{pebble-limit rule}
      \State add $v$ to $\mathrm{clean}(g)$; finalize $g$; $c\gets0$
    \ElsIf{$v$ feeds a 2-input AND $u$ with an}
    \State \hspace{1em}intermediate co-fanin $\wedge\, v\notin\mathit{visited}$
      \State add $v$ to $\mathrm{clean}(g)$; finalize $g$; $c\gets0$
      \State \textbf{break}
    \Else
      \State add $v$ to $\mathrm{dirty}(g)$; $c \gets c+1$
      \Comment{Rule 4: no finalize}
    \EndIf
    \State $\mathit{visited} \gets \mathit{visited} \cup \{v\}$
  \EndFor
\EndFor
\State finalize any non-empty trailing $g$
\State \Return $\mathit{gates}$
\end{algorithmic}
\end{algorithm}

Every finalizing rule is guarded by $\mathit{visited}$, so a node
reachable from multiple paths (fan-out $>1$) -- including a shared
XOR node -- is assigned to exactly one gate, the first time it is
reached; later paths simply skip past an already-visited node. This
removes the need for a post-hoc merge pass and guarantees that the
induced gate-dependency graph is acyclic, since it is derived
directly from $G$'s own topological order. A node is registered as a
\emph{dependency} of $g$ only at the exact moment it is inserted into
$g$'s clean/dirty lists -- never merely because traversal passed over
an already-finalized node belonging to a different, earlier gate --
which was found to be essential for avoiding spurious cross-gate
dependency cycles.

\emph{Current implementation note.} In the present
\texttt{pebbling\_solver.py} codebase, Algorithm~\ref{alg:gategroup}
has been generalized beyond a strict pebble-limit rule. Phase~1 of
\texttt{build\_gate\_groups} performs a greedy, topological-order fill
that admits nodes into the current group until a \emph{hard
per-group weight ceiling} equal to \texttt{max\_pebbles} would be
exceeded (an XOR node always contributes weight $0$ and is exempt
from this ceiling, matching Rule~5 of~\tabref{fig-gadgets}), at which
point the group is finalized and a new one started. A later pass,
\texttt{\_split\_mixed\_po\_groups}, enforces the invariant that no
single group's output set simultaneously contains a genuine primary
output and a non-primary-output node -- splitting any group that
violates this before gate-level scheduling begins. Two additional
phases specifically target the kind of structural symmetry exercised
by circuits like \texttt{bar} (a barrel shifter): a
\emph{shared-fanout-consumer cost exemption}, which avoids
double-charging pebble weight for a producer whose value is consumed
by multiple sibling gates, and a \emph{sibling fanout merging} phase,
which co-locates fanout siblings of a common producer into the same
group when doing so does not violate the weight ceiling. The
\emph{topological order} Phase~1 walks in is itself a tunable
parameter (\texttt{topo\_order}, one of \texttt{"creation"},
\texttt{"dependency\_chain"}, or \texttt{"breadth\_first"}), since
which nodes end up spatially adjacent in traversal order directly
determines which nodes are eligible to be grouped together;
\texttt{"breadth\_first"} in particular keeps all siblings of a shared
fanout producer adjacent, reducing the work the later merge phases
need to do.

\section{Gate-Level Pebbling}

\texttt{GatePebbleSolver} re-applies the same three clause families
of Section~III, but over gate identifiers rather than node
identifiers: $p_{g,i}$ denotes whether gate $g$ is ``on'' at step
$i$, move clauses require a gate's producer gates (derived from
$\mathrm{fanin}$ relations of its dependency nodes) to be pebbled
before and after a toggle, and the cardinality clause is restricted
to \emph{AND-type} gates only:
\begin{equation}
\bigwedge_{i}\Big(\sum_{g:\ \mathrm{counts}(g)} p_{g,i} \le P\Big),
\end{equation}
where $\mathrm{counts}(g)$ excludes gates whose $\mathrm{clean}(g)$
is a single XOR node with no dirty pebbles, since the CNOT-cascade
gadget for XOR needs no ancilla. Gates owning a primary output are
additionally constrained to remain pebbled at $K$, mirroring the
node-level final clause; without this refinement the empty schedule
($K=0$) would trivially satisfy the naive ``all gates off'' final
condition.

\emph{Scheduling method (current default).} The present codebase
treats this Z3-based search, exposed as
\texttt{find\_best\_gate\_pebbling\_by\_tcount}, as an
\emph{opt-in} mode (\texttt{--use-tcount-search}) rather than the
default scheduling path. By default, \texttt{run\_our\_pipeline} now
calls \texttt{pebble\_gates\_greedy\_first}, a greedy scheduler that
is substantially cheaper to run on large circuits (e.g.\ EPFL
benchmarks with thousands of gates) than an incremental SAT search
over every candidate step count. If greedy scheduling deadlocks
--- which can occur only if the caller supplies a
\texttt{solve\_max\_pebbles} smaller than \texttt{grouping\_max\_pebbles}
--- the error propagates directly as a row-level failure by default;
a \texttt{--sat-fallback} flag restores the previous behavior of
silently retrying via the Z3-based search on a greedy deadlock. The
\emph{grouping} pebble budget passed to \texttt{build\_gate\_groups}
and the \emph{scheduling} pebble budget passed to the scheduler are
tracked as two independent quantities (auto-sized, by default, to
$2\times|O|$ and $2\times$ the grouping budget respectively) rather
than a single reused value, since the hard per-group weight ceiling
introduced above means the scheduling budget must always be at least
as large as the grouping budget for any schedule to exist.

\section{Qubit Assignment and Circuit Synthesis}

A solved gate-level schedule is replayed deterministically
(\texttt{assign\_qubits\_to\_pebbling}) to assign physical qubit
indices: non-XOR clean-pebble nodes are allocated a fresh
guaranteed-$\ket{0}$ qubit and freed at their gate's uncompute event;
XOR clean-pebble nodes instead \emph{alias} the qubit of one of their
own fanins, since an XOR is computed in place via a CNOT cascade;
dirty-pebble nodes are reclaimed eagerly immediately after their own
gate's compute step, since no other gate ever depends on them. A
liveness assertion verifies no two simultaneously-live non-aliased
nodes ever share a qubit. Each node is finally synthesized into a
symbolic Clifford+T gadget via one of six rules keyed on fan-in/fan-out
structure (Toffoli-to-T-gate decompositions for AND nodes, a CNOT
cascade for XOR nodes), and gadgets are replayed onto a Qiskit
circuit for QASM export.

\section{Experimental Comparison Against Caterpillar}
\label{sec-caterpillar-comparison}

To validate the T-count claims above against an independent,
externally maintained synthesis pipeline, we built a comparison
harness (\texttt{run\_caterpillar\_experiments.py}) that runs both
this project's own gate-level pebbling pipeline and
\texttt{gmeuli/caterpillar} on the identical input circuit, exported
as a combinational BLIF file, and reports T-count side by side. Since
\texttt{xagtdep} does not itself expose a Python binding for
caterpillar, the harness shells out to a small companion C++ binary,
\texttt{test/blif\_to\_tcount.cpp}, which parses a BLIF file via a
shared reader (\texttt{test/blif\_common.hpp}), synthesizes it with
caterpillar's \texttt{xag\_pebbling\_mapping\_strategy} (or, if built
without Z3, the structural \texttt{xag\_mapping\_strategy}), and
prints a single-line JSON summary of gate and T-counts.

\subsection{Caterpillar's T-count Convention}

Caterpillar's reported T-count is \emph{not} an estimate under any
magic-state-injection model -- every T-gate counted is a literal
non-Clifford gate present in the synthesized circuit, derived by
replaying \texttt{caterpillar::decompose\_with\_ands}'s exact
decomposition pattern over the \texttt{stg\_gate} netlist that
\texttt{logic\_network\_synthesis} produces. Concretely, T-count is
driven entirely by the number of \emph{distinct} AND triples
$(c_1, c_2, t)$ that occur among the two-controlled gates in the
netlist: the first time a given triple appears (its \emph{compute}),
it is charged $6$ T-gates, $6$ CNOTs, and $2$ Hadamards, following a
standard Toffoli-to-Clifford+T decomposition; a later recurrence of
the \emph{exact same} triple (its \emph{uncompute}, via the
measurement-based free-uncompute trick) is charged $0$ T-gates. This
convention differs structurally from this project's own gadget-rule
costs (Rule~1--4 of \tabref{fig-gadgets}, costing $4$, $6$, $7$, and
$0$ T-gates respectively): caterpillar's compute-side cost of $6$ is
not directly comparable to Rule~1's relative-phase cost of $4$, so
any residual T-count gap between the two pipelines reflects, in part,
a genuine difference in gadget-costing convention rather than purely
a difference in circuit structure or scheduling quality.

An additional \texttt{corrected\_t} metric,
$2 \cdot t_{\mathrm{count}} - \mathrm{and\_pos}$, is also reported,
where $\mathrm{and\_pos}$ is the number of primary outputs directly
driven by an AND node. This correction compensates for the
\emph{reverse} direction of the asymmetry above -- caterpillar's raw
$t_{\mathrm{count}}$ implicitly assumes every output-driving AND can
be uncomputed for free, which is not generally available to this
project's own pipeline for genuine primary outputs (since a PO's
value must be retained, not uncomputed) -- giving a fairer
apples-to-apples total once both conventions are reconciled.

\subsection{BLIF Reader Parity}

Two correctness issues were found and fixed in
\texttt{test/blif\_common.hpp} during this validation effort, both of
which previously caused catastrophic parse failures (not merely
inaccurate counts) on realistic circuits:

\begin{enumerate}
\item \textbf{Permissive 2-input/1-input cover fallback.} The shared
  reader had been tightened, relative to the original
  \texttt{blif\_to\_tcount.cpp}'s hand-rolled parser, to require an
  \emph{exact} \texttt{"11 1"} cover match for a 2-input AND node
  (and an exact \texttt{"1 1"} match for a 1-input buffer), throwing
  on any other non-XOR cover. The original parser's convention was
  strictly more permissive: any 2-input cover that does not match the
  canonical XOR/XNOR pattern is treated as AND unconditionally, and
  any 1-input cover that is not the canonical NOT pattern is treated
  as a buffer unconditionally. Restoring this permissive fallback was
  necessary to synthesize the EPFL \texttt{bar} (barrel shifter)
  benchmark, whose BLIF contains at least one differently-formatted
  (but semantically equivalent) AND cover that the stricter check
  rejected.
\item \textbf{Zero-fanin constant \texttt{.names} blocks.} The reader
  previously had no handling at all for a \texttt{.names} block with
  \emph{zero} fanins -- a bare constant signal, written by
  \texttt{mockturtle::write\_blif} (but never by this project's own
  \texttt{pebbling\_solver.write\_blif}) whenever an optimized XAG
  retains a dangling or directly-used constant node. This case only
  surfaces when a BLIF file has been round-tripped through an
  external mockturtle-based tool, as described in
  \secref{sec-pre-optimize} below; it was fixed by interpreting a
  single \texttt{"1"} cover row as constant-true and anything else
  (including an empty cover) as constant-false.
\end{enumerate}

\subsection{Symmetric Pre-Optimization Mode}
\label{sec-pre-optimize}

A second companion shim, \texttt{test/blif\_optimize.cpp}, wraps
three mockturtle XAG optimization passes --
\texttt{xag\_constant\_fanin\_optimization} (\texttt{const\_fanin}),
NPN-resynthesis-based \texttt{cut\_rewriting} (4-input cuts), and
free-XOR-aware \texttt{resubstitution\_minmc\_withDC}
(\texttt{resub}) -- behind the same read/optimize/write-BLIF JSON
contract as \texttt{blif\_to\_tcount}. The experiment harness's
\texttt{--pre-optimize \textless pass\textgreater} /
\texttt{--optimizer-bin} flags run exactly one such pass \emph{once}
per benchmark, \emph{before} either pipeline sees the circuit, and
feed the \emph{identical} resulting optimized BLIF file into both
this project's own pipeline (via a fresh \texttt{read\_blif} re-parse)
and into caterpillar -- keeping the comparison symmetric, so that any
T-count delta reflects a genuine difference in synthesis strategy
rather than one pipeline seeing a different (optimized vs.\
unoptimized) circuit than the other. If the optimization pass itself
fails for a given benchmark, that row is recorded with the error and
\emph{neither} pipeline is run for it, rather than silently falling
back to the unoptimized circuit for one pipeline only.

\subsection{Empirical Findings on the EPFL \texttt{bar} Benchmark}

Running this harness on the EPFL \texttt{bar} (barrel shifter, 135
PIs, 128 POs, 3336 gates in its original EPFL-authored BLIF) surfaced
three findings of independent interest.

\textbf{(1) A BLIF round-trip artifact dominates the naive,
unoptimized comparison.} Feeding caterpillar and this project's own
pipeline the pristine, EPFL-authored \texttt{bar.blif} directly gives
$\mathrm{ours}\text{-}T = 30448$ against a corrected caterpillar
T-count of $17932$ -- a ratio of $1.698$, naively suggesting
caterpillar synthesizes a substantially cheaper circuit. However,
simply round-tripping the \emph{same, logically unchanged} circuit
through \texttt{blif\_optimize --pass=const\_fanin} (which found
\emph{zero} nodes to fold: $\mathrm{nodes\_before} =
\mathrm{nodes\_after} = 1505$) and re-feeding the result to both
pipelines drops $\mathrm{ours}\text{-}T$ to $17736$ against an
\emph{unchanged} corrected caterpillar T-count of $17932$ -- a ratio
of $0.989$. Since no AND-gate content changed (caterpillar's T-count,
being driven solely by distinct AND triples, is exactly invariant
across this round-trip), essentially the entire original $1.698\times$
gap is attributable to how \texttt{pebbling\_solver}'s gate-grouping
is sensitive to the specific \texttt{.names}-level encoding of
XOR/buffer/NOT chains that \texttt{mockturtle::write\_blif} happens
to emit, as distinct from the original EPFL file's own encoding --
not to any real difference in optimization quality between the two
pipelines. This round-trip-artifact-vs-real-optimization distinction
is the key caveat attached to every pre-optimized result reported
here, and is flagged as an open item for further investigation.

\textbf{(2) Real structural optimization does close part of the
remaining gap, and moves caterpillar's own number too.} Unlike
\texttt{const\_fanin}, \texttt{cut\_rewriting} found genuine
reductions on \texttt{bar} ($\mathrm{nodes\_before} = 1505 \to
\mathrm{nodes\_after} = 1398$, a $\sim\!7\%$ reduction), consistent
with a barrel shifter's substantial structural symmetry (every bit
position and every shift stage reusing the same small set of
shift-amount control signals) being exploitable at the local
cut-rewriting level even though it is invisible to
\texttt{const\_fanin}'s narrower algebraic-cancellation pattern. This
is also the only pre-optimization run in which caterpillar's own
corrected T-count actually moved ($17932 \to 16648$), landing at a
final ratio of $1.032$ ($\mathrm{ours}\text{-}T = 17180$).

\textbf{(3) Caterpillar's mapping strategies perform no internal
logic-level optimization.} All three available caterpillar
strategies used by \texttt{blif\_to\_tcount} --
\texttt{xag\_pebbling\_mapping\_strategy},
\texttt{xag\_mapping\_strategy}, and
\texttt{xag\_low\_depth\_mapping\_strategy} (used elsewhere in this
codebase's LLVM integration) -- are purely scheduling/mapping
strategies operating on the XAG's AND/XOR structure \emph{as given};
none restructure the logic network itself, and there is no
caterpillar-side equivalent of \texttt{xag\_constant\_fanin\_
optimization}, \texttt{cut\_rewriting}, or \texttt{resubstitution}.
The flat caterpillar T-count observed across the unoptimized and
\texttt{const\_fanin}-processed runs is therefore fully explained by
the AND-subgraph being byte-for-byte identical in both cases, not by
any internal caterpillar-side optimization absorbing the pre-pass.

\subsection{A Circuit Class Favoring the Dirty-Ancilla Heuristic}

The gadget-costing asymmetry noted above -- Rule~1's relative-phase
compute/free-uncompute cost of $4$ T-gates per internal AND node,
against caterpillar's literal $6$-T compute cost with $0$-T reuse
available \emph{only} for an exactly-recurring AND triple -- suggests
a circuit class where the dirty-ancilla heuristic should win cleanly:
a sum of disjoint two-input AND terms XOR-accumulated into a single
output, i.e.\ $\mathrm{out} = \bigoplus_{k} (x_{2k} \wedge x_{2k+1})$.
Every AND term in such a circuit is purely internal (it fans into
exactly one XOR accumulator and is never itself a primary output),
making it an ideal fit for Rule~1, while every term is also
structurally distinct, so caterpillar's exact-triple-recurrence
discount never applies. A representative 10-input, 5-term instance
of this family,
\[
\mathrm{out} = (x_0 \wedge x_1) \oplus (x_2 \wedge x_3) \oplus
(x_4 \wedge x_5) \oplus (x_6 \wedge x_7) \oplus (x_8 \wedge x_9),
\]
synthesized at a tight pebble budget (\texttt{max\_pebbles=2}, which
forces the greedy scheduler into exactly the compute$\to$fold-via-XOR
$\to$uncompute$\to$reuse pattern Rule~1 is designed for), is expected
to cost $5 \times 4 = 20$ T-gates under this project's own pipeline
against $5 \times 6 = 30$ T-gates under caterpillar's convention --
a predicted $33\%$ advantage for the heuristic that scales linearly
with the number of XOR-accumulated AND terms. Confirming this
prediction empirically (rather than relying on the convention-level
argument alone) is left as a direct next validation step using the
same harness described above.
